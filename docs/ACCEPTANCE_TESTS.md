# MVP 인수 기준 및 검수 시나리오

사용자 관점의 기대 결과를 정리한 검수 계획이다. 내부 검수는 가상 등기 대상·문서와 모의 공급자 사례로 설계한다. 실제 공급처의 지원 범위와 개인정보 처리 기준은 [검증 항목](RESEARCH.md)과 [결정 기록](DECISIONS.md)에 근거를 남긴다.

이번 MVP의 필수 인수 흐름과 실제 연동 범위는 [MVP 개발 계획서](MVP_DEVELOPMENT_PLAN.md)를 따른다. 아래 시나리오에서 실사용 회원가입, 실제 문서의 처리와 외부 메시지 발송은 운영 검증 단계에 적용한다.

내부 검수에서는 앱에서 받은 예시 PDF·PNG를 파일 선택으로 올린다. `내 정보 > 업로드 이력`에서 본인의 제출 결과를 확인하고, 해당 등기 대상의 `이력 보기`에서 공유 문서 버전과 모의 신청·완료 사건을 확인한다.

## Phase 1. 지도 조회와 공유

| ID | 상황과 동작 | 통과 기준 |
| --- | --- | --- |
| P1-01 | 주소·지번·건물명으로 같은 위치를 검색한다. 검색 결과가 없는 입력도 사용한다. | 검색 의도에 맞는 후보를 확인할 수 있다. 결과 없음이 표시되고 검색어를 다시 편집할 수 있다. |
| P1-02 | 같은 지도 건물에 서로 다른 두 호수의 등기 대상이 있다. 두 대상을 차례로 연다. | 선택한 호수와 대상별 자료·상태가 일치하고, 한 호수의 자료나 관심 상태가 다른 호수에 표시되지 않는다. |
| P1-03 | 공유 자료가 없거나 위치에서 고유번호를 확인할 수 없다. | 자료 미등록과 등기 대상 확인 불가가 서로 구분된다. |
| P1-04 | 선택한 대상과 문서 고유번호가 일치하는 PDF를 제출한다. 이미지 제출도 같은 흐름으로 확인한다. | 검수와 공유 범위 확인까지 마친 자료가 해당 대상에 표시된다. 열람·발급 시각과 등록 시각이 구분된다. |
| P1-05 | 다른 호수 문서, 고유번호를 읽을 수 없는 파일, 또는 마스킹 누락이 있는 자료를 제출한다. | 게시가 보류되고 제출자가 처리 상태를 볼 수 있다. 검수 중인 자료가 다른 회원에게 노출되지 않는다. |
| P1-06 | 동일 문서를 재제출하고, 기존 문서보다 이전에 열람한 별도 문서를 늦게 제출한다. | 재제출로 공유 문서 버전이 늘어나지 않는다. 이전 자료는 과거 버전으로 연결되며 더 최근에 열람한 문서를 덮어쓰지 않는다. |
| P1-07 | 권한이 없는 회원이 원본 또는 다른 회원의 제출 결과에 접근을 시도한다. | 화면과 직접 접근 경로 모두 정책 범위 안의 자료만 제공하고, 제출 기록의 접근 권한이 적용된다. |
| P1-08 | 마스킹된 자료의 화면 표시, 텍스트 추출, 파일 다운로드를 확인한다. 게시 중단된 사본을 다시 연다. | 정책에 따라 가려진 값이 공유 경로에서 드러나지 않고, 게시 중단 후 동일 경로의 접근이 차단된다. |
| P1-09 | 지도 검색 후 대상을 열고 닫는다. 좁은 화면에서도 같은 동작을 확인한다. | 선택한 주소·동·호수와 핵심 문서 상태를 확인할 수 있고, 상세를 닫으면 기존 위치와 검색 결과에서 탐색을 이어갈 수 있다. |
| P1-10 | 가입하고 로그인한 뒤 마이페이지를 연다. | 본인이 공유한 자료의 검수 상태와 계정 설정을 확인할 수 있다. |

## Phase 2. 변동 모니터링과 알림

| ID | 상황과 동작 | 통과 기준 |
| --- | --- | --- |
| P2-01 | 여러 회원이 같은 고유번호를 관심 등록하고 같은 주기에 확인한다. | 대상별 일반 조회가 한 번 실행되고, 새 사건이 있으면 해당 회원에게 알림이 생성된다. |
| P2-02 | 성공 조회 중 새 변동이 없고 그다음 조회는 실패한다. | 성공 조회 시각과 당시 결과가 보존되며 이후 조회 실패가 별도로 표시된다. |
| P2-03 | 등기신청 접수, 등기 완료, 완료가 반영된 새 문서 확보가 순서대로 발생한다. | 접수와 완료가 구분된다. 완료 감지로 갱신 필요가 표시되고, 반영됐음을 확인한 문서를 확보하면 해당 사건의 표시가 해소된다. 금액과 권리관계는 문서에서 확인된 값으로만 갱신된다. |
| P2-04 | 갱신이 필요한 대상에서 새 변동 미감지 응답이 오거나, 완료 이후에 접수 상태가 늦게 도착한다. | 미감지 결과로 갱신 필요 표시가 사라지지 않는다. 늦게 받은 상태는 공급처에 대해 정한 순서·정정 규칙에 따라 처리한다. |
| P2-05 | 같은 상태의 같은 사건이 반복 수신되거나 처리 중 중단된 작업이 재개된다. | 같은 사건의 같은 상태에 대한 알림이 회원·채널별로 중복 생성되지 않는다. |
| P2-06 | 회원이 관심 등록을 해제하거나 알림톡을 끈 뒤 발송 작업이 진행된다. | 현재 관심 등록과 채널 설정에 따라 발송 대상이 결정된다. |
| P2-07 | 서비스 내 알림 생성은 성공하고 알림톡 발송은 실패하거나 결과가 불명확하다. | 서비스 내 알림을 확인할 수 있다. 외부 발송 실패 및 결과 미확인 상태를 각각 기록하고 해당 연동에 정한 복구 기준을 적용한다. |
| P2-08 | 첫 조회의 응답에 관심 등록 이전에 발생한 사건이 포함된다. | D05에서 정한 첫 조회 기준을 적용하며 기존 사건과 관심 등록 이후의 새 변동을 구분한다. |
| P2-09 | 한 대상에 동시에 진행 중인 신청 두 건 중 한 건만 완료된다. | 두 신청의 상태를 각각 확인할 수 있다. 한 신청의 완료가 다른 신청의 진행 상태를 바꾸지 않는다. |

## 검수 결과 기록

시나리오 ID, 사용한 자료와 공급처, 확인한 환경, 실제 결과, 증빙, 남은 결함을 기록한다. 공급처나 정책이 정해져야 확인할 수 있는 항목은 연결된 결정 ID와 확인 조건을 함께 남긴다.
