# 기술 및 운영 검증 항목

현재 문서는 확인할 질문과 판단 기준을 기록한다. 아래 항목은 미확정이다.

| 검증 항목 | 확인할 내용 | 영향을 받는 결정 |
| --- | --- | --- |
| 공식 데이터 제공 | 대법원·인터넷등기소·등기정보광장에서 개별 등기 대상의 변동 여부, 신청 및 처리 상태, 완료를 각각 확인할 수 있는 공식 연동 수단이 있는지 조사한다. | 직접 연동 가능성, 모니터링에서 표시할 수 있는 사건 |
| 자동 조회 허용 범위 | 공식 이용 조건에 비춰 자동·대량·반복 조회 허용 여부, 인증 조건, 요청 제한, 응답의 저장·이용 범위를 확인한다. | 주기 조회 가능성, 허용되는 접근 방식과 운영 범위 |
| 식별정보와 지도 매칭 | 토지·건물·집합건물 사례에서 지도 검색 결과와 등기 고유번호를 연결할 수 있는지 확인한다. 변동 조회에 고유번호 외에 소유자 이름 등 추가 정보가 필요한지 확인한다. | 대상 선택 흐름, 오연결 방지, 개인정보 처리 범위 |
| 갱신 주기와 비용 | 실제 데이터 반영 지연과 조회 단가·과금 단위를 조사한다. 고유번호별 중복 제거를 반영해 하루 세 번 조회의 예상 비용을 검토한다. | 실제 확인 주기, 무료 운영 비용의 부담 방식 |
| 민간 API 대안 | 등기고·에이픽 등 후보에 대해 조회 단위, 반환 상태, 이용 제한, 비용, 장애 대응, 결과의 저장·공유 조건을 비교한다. | 공식 연동이 어렵거나 운영상 불리할 때 사용할 공급처 |
| 문서와 파싱 결과의 공유 | 원본 PDF·이미지, 마스킹된 사본, 구조화된 항목 각각에 대해 저장·공유 가능한 범위와 접근 조건을 법적으로 검토한다. | 지도와 상세 화면에 노출할 정보, 회원 참여형 공유의 제공 범위 |
| 원본 검증과 개인정보 | 문서 위변조 확인 방법과 검증 한계를 확인한다. 마스킹 대상, 검수 방식, 원본 저장 여부 및 보관·삭제 정책을 검토한다. | 문서 수용 및 공개 기준, 접근 권한과 보관 방식 |
| 기술 스택 및 서비스명 | 외부 연동, 지도 매칭, 문서 처리와 운영 제약을 확인한 뒤 기술 후보를 평가한다. 서비스명은 별도로 정한다. | 구현 기반과 서비스 식별 |

공식 연동의 조사 시작점은 인터넷등기소, 등기정보광장 및 등기정보광장 Open API다. 지도·주소 매칭에는 공공데이터포털의 관련 데이터와 지도 API를 후보로 검토한다. 검증 결과에는 출처, 확인 날짜, 제공 항목, 이용 조건, 남은 질문을 기록한다. 민간 업체 내부의 수집 방식은 확인된 근거가 있을 때만 기록한다.

## 공급처 공개 문서 검토 · 2026-11-25

| 후보 | 문서에서 확인한 범위 | 운영 연동 전에 확인할 사항 |
| --- | --- | --- |
| 등기고 | 부동산 검색, 고유번호 기반 등기 열람, 변동 모니터링과 웹훅을 문서화했다. 샌드박스 키는 검색·열람의 가상 JSON을 반환한다. 샌드박스에서 등록한 모니터링과 웹훅의 실제 전송은 운영 환경에서 별도로 확인해야 한다. [등기고 개발자 문서](https://deunggigo.kr/api-guide) | 하루 1회 확인 주기, 알림 등록 시 필요한 수신자와 소유자 정보, 웹훅 수신 요청의 출처 확인 방법을 검토한다. 문서의 전송 ID는 중복 처리에 쓰이며 요청 자체의 진위를 확인할 필요가 있다. |
| 에이픽 | 공개된 부동산 등록 입력은 지번 중심이다. 기준 상태를 기록한 뒤 하루 한 번 확인하며, 변동을 감지하면 해당 모니터링을 종료한다. 등록, 확인, 결과 조회의 과금 방식이 각각 문서에 있다. [에이픽 모니터링 가이드](https://apick.app/dev_guide/iros_monitor) | 공개 등록 파라미터에서 동·호수나 부동산 고유번호를 확인하지 못했다. 인접한 두 호수를 별개로 겨냥할 수 있는지, 재등록 시 같은 사건의 반복 감지 또는 접수 이후 완료 누락이 있는지 검증한다. |
| 대법원 등기정보광장 | 공개 안내와 Open API 신청 페이지를 확인했다. [등기정보광장 Open API 안내](https://data.iros.go.kr/rp/oa/openOapiAppl.do) | 서비스에서 개별 등기 대상의 상태를 정기 조회할 수 있는 공개 API와 이용 조건은 확인되지 않았다. |

첫 API 검증은 샌드박스 키로 한 주소를 검색하고 응답 구조와 고유번호 표기를 확인하는 범위로 시작한다. 실제 동·호수 구분, 관측 가능한 상태, 갱신 지연, 웹훅 출처 검증과 비용은 공급처 승인 및 테스트 대상이 준비되면 점검한다. 샌드박스 결과에는 모의 응답임을 기록한다.
