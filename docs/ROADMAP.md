# 단계별 개발 계획

현재 착수 범위는 [MVP 개발 계획서](MVP_DEVELOPMENT_PLAN.md)를 따른다. 실제 지도 API와 가상 등기·변동 데이터로 사용자 흐름을 검증한다. 아래 단계는 실제 자료와 운영 연동까지 고려한 제품 로드맵이다.

## Phase 0. 기술 및 운영 타당성 검증

- 공식 등기변동 연동과 자동 조회 조건을 확인하고 민간 API 후보의 비용과 이용 조건을 비교한다.
- 문서 원본과 추출 정보의 저장·공유 범위를 검토한다.
- 토지·건물·집합건물 사례로 지도 검색 결과와 부동산 고유번호를 매칭할 수 있는지 확인한다.
- **완료 기준** — 공유에 사용할 수 있는 정보, 부동산을 식별할 수 있는 방법과 한계, 사용할 수 있는 변동 데이터의 범위 및 비용을 근거와 함께 기록한다. 확인 결과에 따라 다음 단계의 제공 범위를 정한다.

검증 근거는 [검증 항목](RESEARCH.md), 기능별 결론은 [결정 기록](DECISIONS.md)에 남긴다.

## Phase 1. 지도 기반 등기 조회 및 공유

- 회원 기능, 지도 검색, 등기 대상 선택과 상세 조회를 구축한다.
- PDF·이미지 등록, 대상 식별, 파싱, 마스킹, 검수, 중복 확인과 버전 관리를 연결한다.
- 확인된 허용 범위에 맞춰 공유 자료를 표시하고 이용자가 문서의 기준 시점을 확인할 수 있게 한다.
- **완료 기준** — 같은 건물의 서로 다른 등기 대상을 구분하고 검수된 문서 정보를 정확한 대상에 연결한다. 여러 문서 버전과 문서 미등록 상태를 구분해 조회할 수 있다.

화면과 자료 처리의 검수는 [Phase 1 인수 기준](ACCEPTANCE_TESTS.md#phase-1-지도-조회와-공유)을 참조한다.

## Phase 2. 등기변동 모니터링

- 관심 등록과 알림 설정, 승인된 데이터 공급처 연동, 대상별 주기 조회, 변동 상태 비교와 사건 저장을 구축한다.
- 서비스 내 알림과 카카오톡 알림톡을 연동하고 문서 갱신 필요 상태를 상세 화면에 표시한다.
- **완료 기준** — 같은 대상을 여러 회원이 등록해도 확인 주기별 외부 조회가 중복되지 않는다. 확인된 신청 및 완료 사건과 조회 실패를 구분하고, 발생한 변동을 관련 회원에게 알린다.

조회와 발송 결과의 검수는 [Phase 2 인수 기준](ACCEPTANCE_TESTS.md#phase-2-변동-모니터링과-알림)을 참조한다.

## Phase 3. 향후 확장

실거래가·시세 연계, 전세사기 위험 요소 분석, 근저당권·담보 분석, 권리관계 변경 타임라인, 금융 실무자용 다중 부동산 관리, 지역별 변동 통계를 검토한다. 초기 MVP 범위에서는 제외한다.
