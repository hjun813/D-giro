# 화면 및 사용자 흐름

이 문서는 [요구사항](REQUIREMENTS.md)을 화면 흐름으로 옮긴 검토안이다. 화면을 구성할 때 지도에서 고른 위치, 현재 선택한 등기 대상, 화면에 표시한 자료의 기준 시점을 사용자가 확인할 수 있게 한다.

화면 배치와 표시 상태의 상세 기준은 [UI 명세](UI_SPEC.md), 공통 스타일은 [디자인 시스템](DESIGN_SYSTEM.md)을 따른다.

## 지도에서 등기 대상 선택

1. 사용자가 주소·지번·건물명을 입력하면 일치하는 위치 후보를 보여 준다. 결과가 없으면 수정할 수 있도록 검색어를 유지한다.
2. 위치를 선택하면 토지·건물·집합건물 등기 대상 후보를 보여 준다. 집합건물은 동·호수를 명시적으로 선택할 수 있게 한다. 후보가 여러 개거나 매칭이 불확실하면 선택을 유도하거나 확인이 필요함을 표시한다.
3. 등기 대상이 결정되면 상세에 해당 주소·동·호수와 공유 자료 유무를 표시한다. 상세의 공유 및 관심 등록 동작은 이 선택에 연결된다.

지도는 탐색에 쓰고, 상세는 선택한 대상의 정보를 읽는 데 초점을 둔다. 화면이 좁으면 지도 아래에서 상세를 열고 닫을 수 있게 하는 구성을 우선 검토한다. 상세를 닫은 뒤에는 검색 결과와 지도 위치를 이어서 탐색할 수 있게 한다.

## 등기 대상 상세의 표시 우선순위

| 영역 | 표시 내용 |
| --- | --- |
| 선택한 대상 | 주소, 유형, 집합건물의 동·호수 |
| 공유 자료 | 자료 등록 여부, 문서의 열람·발급 일시, 서비스 등록 일시, 제공이 허용된 권리관계 및 문서 |
| 변동 확인 | 마지막으로 확인에 성공한 시각, 최근 확인 결과, 확인된 신청·처리 상태, 기존 자료의 갱신 필요 여부 |
| 관련 동작 | 등기 자료 공유, 관심 등록·해제, 변동 이력 확인 |

상태 문구는 시점과 사실을 드러낸다. 아래 문구는 검토용 예시다.

| 상황 | 표시 예시 |
| --- | --- |
| 대상 확인 완료, 자료 미등록 | 공유된 등기 정보가 없습니다. |
| 위치에서 대상 확인 불가 | 이 위치의 등기 대상을 확인하지 못했습니다. |
| 외부 확인 성공, 새 변동 미감지 | 최근 조회에서 새 변동이 감지되지 않았습니다. |
| 신규 신청 확인 | 등기신청 접수가 확인됐습니다. |
| 완료 확인, 반영된 문서 미확보 | 등기 완료가 확인됐습니다. 공유 자료를 갱신해야 합니다. |
| 최근 외부 확인 실패 | 최근 변동 확인에 실패했습니다. 마지막 성공 확인 시각을 표시합니다. |

최근 조회 결과와 문서 갱신 필요 상태는 동시에 표시할 수 있다. 예를 들어 기존 자료의 갱신이 필요한 대상에서 다음 확인이 실패했다면 두 사실을 함께 보여 준다. 최신 공식 문서가 필요한 사용자에게는 새로 열람·발급한 등기사항증명서를 확인하도록 안내한다.

## 자료 공유

1. 등기 대상 상세에서 공유를 시작하고, 원래 선택한 대상과 업로드한 PDF·이미지에서 식별된 대상을 확인한다.
2. 대상이 다르거나 고유번호를 읽지 못하면 게시를 보류한다. 사용자가 파일, 선택한 대상 또는 검수 상태를 확인할 수 있게 한다.
3. 추출·마스킹 결과를 검수한다. 마스킹 검수 중에는 공유된 자료 목록에 표시하지 않는다.
4. 같은 문서가 이미 있는 경우 기존 자료를 안내하고, 다른 시점의 문서라면 검수 후 버전 이력에 연결한다. 사용자는 마이페이지에서 본인이 올린 자료의 처리 상태를 확인한다.

## 관심 등록과 알림

- 상세에서 선택한 등기 대상을 관심 등록한다. 관심 목록에서 대상별 확인 상태, 마지막 성공 시각, 알림 설정과 해제 동작을 제공한다.
- 알림에는 신청 접수와 등기 완료를 구분하고, 확인한 범위에서 해당 사건을 표시한다. 서비스 내 상세에서 대상과 상태를 다시 확인할 수 있게 한다.
- 알림톡에 넣을 내용과 링크의 접근 방식은 [정보 처리 기준](DATA_GOVERNANCE.md)과 [외부 연동 설계](ARCHITECTURE.md)에 따라 검토한다.
