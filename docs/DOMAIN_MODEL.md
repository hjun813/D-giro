# 데이터와 상태 설계

이 문서는 [요구사항](REQUIREMENTS.md)의 데이터 관계를 검토하기 위한 논리 모델이다. 각 항목은 도메인 개념으로, 저장 구조와 실제 필드는 공급처와 기술 스택을 확인한 뒤 정한다.

## 주요 데이터

| 데이터 | 처리에 필요한 정보 | 연결 |
| --- | --- | --- |
| 지도 위치 | 검색용 주소·지번·건물명, 제공되는 위치 식별값 | 한 위치에서 여러 등기 대상 후보를 찾을 수 있다. |
| 등기 대상 | 검증된 부동산 고유번호, 토지·건물·집합건물 유형, 주소와 해당 시 동·호수, 식별 근거 | 문서·변동 확인·관심 등록의 공통 기준이다. |
| 제출 자료 | 업로더, 제출 시각, 선택한 대상, 문서에서 확인한 대상, 추출·검수 결과 | 게시가 보류된 제출도 처리 상태를 남길 수 있다. 원본 저장은 별도 결정 사항이다. |
| 등기 문서 버전 | 대상, 열람·발급 시각, 등록 시각, 출처 및 검수 결과 | 같은 대상에 서로 다른 시점의 확인된 버전이 있을 수 있다. |
| 권리관계 정보 | 문서 내 구분과 근거 항목, 권리 종류, 확인된 설정·말소 정보와 금액 | 추출한 문서 버전에 연결한다. 공유하는 항목은 정보 유형별 정책을 적용한다. |
| 변동 확인 기록 | 대상, 공급처, 확인 시각, 성공·실패, 확인 결과 | 마지막 시도와 마지막 성공을 따로 확인할 수 있게 한다. |
| 등기변동 사건 | 대상, 공급처의 사건 식별 근거, 확인된 신청·처리 상태, 관측 시각, 제공 시 사건 발생 시각 | 한 대상에서 여러 신청이 동시에 진행될 수 있다. |
| 관심 등록 | 회원, 대상, 등록·해제 상태, 알림 설정 | 같은 회원의 같은 대상에 대한 활성 등록은 하나다. |
| 알림 | 사건과 상태 변경, 수신 회원, 채널, 발송 결과 | 같은 사건의 같은 상태 알림을 회원·채널별로 중복 생성하지 않는다. |

## 대상과 문서 연결

- 지도 위치가 일치해도 등기 고유번호가 검증되기 전에는 문서를 기존 등기 대상에 자동으로 연결하지 않는다. 고유번호의 연결 근거와 확인 결과를 남긴다.
- 업로드 시각이 늦더라도 문서의 열람·발급 시각이 이전이라면 이력으로 처리한다. 기준 시각을 확인하기 어렵거나 동일 시각의 문서가 충돌하면 검수에서 해결한다.
- 문서 중복 판정 기준은 샘플로 검증한다. 파일이 같다는 사실과 내용이 같은 문서를 다른 파일로 제출한 경우를 구분해 검토한다.
- 채권최고액은 문서에 적힌 항목명과 값으로 취급한다. 추출하지 못한 금액과 실제 0을 구분한다.

## 상태별 처리

| 관측된 사실 | 관련 데이터 처리 |
| --- | --- |
| 확인 성공, 새 변동 미감지 | 성공 기록과 확인 시각을 남긴다. 이미 감지한 사건과 문서의 갱신 필요 상태는 현재 근거에 따라 유지한다. |
| 확인 실패 또는 결과 해석 불가 | 실패를 기록하고 마지막 성공 시각과 문서·사건 상태를 유지한다. |
| 신청 접수 또는 처리 상태 변경 확인 | 대상과 신청별로 사건을 기록한다. 확인 가능한 유형과 시각만 반영한다. |
| 등기 완료 확인 | 해당 완료가 기존 공유 문서에 반영됐는지 확인이 필요하면 갱신 필요 상태를 표시한다. 권리관계 데이터의 출처는 기존 문서 버전으로 유지한다. |
| 새 문서 확보 | 대상과 기준 시점 및 반영 여부를 확인해 새 버전을 연결한다. 해당 완료 사건이 반영됐음을 확인하면 그 사건의 갱신 필요 상태를 해소한다. |

재조회로 같은 상태를 받은 경우와 과거 상태가 늦게 도착한 경우를 구분한다. 공급처가 응답 순서를 보장하는지, 상태의 정정이나 철회를 어떻게 전달하는지 확인한 뒤 처리 기준을 확정한다.
