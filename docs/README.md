# 개발 전 문서 안내

지도에서 개별 부동산의 등기 정보를 찾고, 허용된 자료를 회원끼리 공유하며, 관심 부동산의 등기변동을 알려 주는 서비스의 기획·설계 문서다.

| 문서 | 검토할 내용 |
| --- | --- |
| [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) | 누구의 어떤 문제를 해결하는가 |
| [REQUIREMENTS.md](REQUIREMENTS.md) | 초기 서비스가 제공해야 할 동작은 무엇인가 |
| [MVP_DEVELOPMENT_PLAN.md](MVP_DEVELOPMENT_PLAN.md) | 실제 지도와 목데이터로 무엇을 개발하고 어디까지 검증하는가 |
| [UX_SPEC.md](UX_SPEC.md) | 지도 탐색부터 자료 공유와 변동 확인까지 화면이 어떻게 이어지는가 |
| [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) | 로고에서 가져온 색상, 글자 위계와 공통 컴포넌트를 어떻게 적용하는가 |
| [UI_SPEC.md](UI_SPEC.md) | PC와 모바일에서 지도·등기 상세와 주요 화면을 어떻게 배치하는가 |
| [DOMAIN_MODEL.md](DOMAIN_MODEL.md) | 위치, 등기 대상, 문서 버전, 변동 사건을 어떻게 연결하는가 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 주요 기능의 책임과 외부 연동의 실패·복구를 어떻게 다루는가 |
| [DATA_GOVERNANCE.md](DATA_GOVERNANCE.md) | 원본, 추출 정보, 공유 자료에 어떤 접근·보관 기준이 필요한가 |
| [RESEARCH.md](RESEARCH.md) | 어떤 외부 근거와 실측이 필요한가 |
| [DECISIONS.md](DECISIONS.md) | 개발 단계별로 어떤 결정이 필요하고 결과를 어디에 기록하는가 |
| [ACCEPTANCE_TESTS.md](ACCEPTANCE_TESTS.md) | 어떤 사례를 통과하면 기능이 의도대로 동작하는가 |
| [ROADMAP.md](ROADMAP.md) | 어떤 순서로 검증하고 구현하는가 |

[요구사항](REQUIREMENTS.md)과 [로드맵](ROADMAP.md)에서 제품 범위를 확인한다. 화면·데이터·연동·운영 문서는 개발 전 검토안이며, 확정이 필요한 내용은 [결정 기록](DECISIONS.md)을 참조한다. 실제 서비스 제공 범위에 영향을 주는 조사 결과가 나오면 결정 근거와 관련 문서를 함께 갱신한다.
