## 단계별 검토 기준

- **Phase 1 지도 조회와 공유** — D01~D03 확인 결과를 바탕으로 대상을 식별할 수 있는 범위와 게시 가능한 자료를 정한다. 식별하기 어려운 유형이나 권한이 확인되지 않은 자료는 해당 결과를 화면과 요구사항에 반영한다.
- **Phase 2 모니터링** — D04·D05·D07 확인 결과를 바탕으로 운영 시 필요한 상태, 확인 주기와 비용을 검토한다. 알림톡 운영 시 D06의 조건을 적용한다. 모의 데이터로 확인한 동작과 실제 공급처의 응답으로 확인한 범위를 각각 기록한다.
- **공통** — 해당 구현에 필요한 기술을 D08에서 정한다. 운영 정책이나 제공 범위가 달라지면 관련 요구사항, 화면 흐름과 [검수 시나리오](ACCEPTANCE_TESTS.md)를 갱신한다.

## 결정 항목 작성 형식

- 항목 ID, 검토 상태, 확인 날짜와 담당자
- 검토한 선택지와 확인한 출처·조건·샘플 범위
- 결론과 선택 이유, 제한 사항 및 재검토 조건
- 영향을 받는 기능, 관련 문서와 검수 시나리오

## 검토 기록

### D04 · D05 모니터링 조회 아키텍처 및 차등 폴링 기준 (2026-11-27)

- **상태**: 아키텍처·폴링 정책 및 민간 등기 데이터 API 미사용 확정. 인터넷등기소 직접 자동 조회 방식과 운영 조건은 미검증이다.
- **검토 근거**: 인터넷등기소 부동산 등기 신청사건 간편검색 직접 확인(고유번호 직접 조회 가능, 로그인 및 소유자/신청인명 필수) 및 [기술 및 운영 검증 항목](RESEARCH.md)
- **결론**:
  1. **고유번호(14자리) 기준 정규화 및 중복 제거**: 동일 고유번호를 여러 회원이 관심 등록해도 외부 조회는 고유번호당 1회만 수행하고, 감지된 변동만 구독자에게 팬아웃한다.
  2. **평일 영업시간 한정 차등 폴링**: KST 평일(주말·공휴일 제외) 등기소 운영시간에 맞춰 조회한다. 기본 티어(`standard`)는 평일 마감 후 1회(18:30), 집중 티어(`intensive`)는 평일 3회(11:00 · 15:00 · 18:30)로 운영한다.
  3. **어댑터 경계(`RegistryMonitorProvider`) 고정**: 실제 공급처와 모의 공급자(`MockMonitorProvider`)를 어댑터 인터페이스로 분리한다. 조회 실패(`failed`, `rate_limited`, `auth_required`)는 변동 미감지로 처리하지 않고 직전 성공 시각과 상태를 보존한 채 재시도 대상으로 분리한다.
- **제한 사항 및 재검토 조건** — 인터넷등기소 직접 어댑터를 연결하기 전에 공식 자동·반복 조회 수단과 이용 조건, 제3자 신청사건(가압류·경매 등)의 조회 범위, 소유자명 필요 여부, 비용과 결과 저장·알림 허용 범위를 확인한다. [인터넷등기소](https://www.iros.go.kr/), [등기정보광장 Open API 안내](https://data.iros.go.kr/rp/oa/openOapiAppl.do)
- **영향 범위**: `src/lib/monitor/*`, 관심 물건 모니터링, 변동 알림 파이프라인
